# AI-Driven Dual-Engine SOC Analytics Subsystem

A decoupled, intelligent security operations center (SOC) pipeline that securely streams raw perimeter security events from a bare-metal OPNsense router, aggregates identical high-consequence vectors, and leverages an LLM-powered analytics processor to generate localized threat intelligence PDF reports.

The subsystem features two specialized analytics pipelines operating side-by-side:
1. **Core Packet Filter Core:** Decodes and filters native FreeBSD layer-3/4 firewall rule violations.
2. **Suricata Network IDS Core:** Deeply inspects layer-7 payload anomalies, signature rule matches, and behavioral intrusion detection metrics.

## 🛠️ Architecture Overview

The subsystem operates across a dual-node topology designed for minimal operational impact on the core perimeter security gateway:

1. **OPNsense Core Security Node:** Runs lightweight shell utilities that dynamically anchor and intercept raw, variable-length log feeds (`filterlog` and `suricata.json`). It isolates explicitly dropped, blocked, or high-priority alert vectors, packages the raw tokens natively into JSON batches, and ships the payloads over an encrypted SSH link.
2. **Quantum Analytics Node (WSL2 / Ubuntu):** Ingests raw data batches, maps transactions against local network topology data, executes aggressive in-memory de-duplication matrices, processes systemic noise via customized exclusion definitions, and pipes high-consequence vectors into an LLM analysis engine to render detailed, formatted PDF violation reports.

## 📁 Repository Organization

* `/OPNsense`: Contains native FreeBSD shell utilities deployed to `/usr/local/bin/` on the router for automated log extraction and shipping.
* `/knowledge-base`: Central repository for local intelligence configurations:
  * `allowlist.json`: Pre-filter exclusions for ignoring expected structural noise.
  * `topology.md`: Deterministic identity dictionary mapping static IPs to physical network assets.
  * `/policy`: Security baseline logics and analysis prompt definitions.
* Root Directory: Contains the primary Python LangChain analytics engines (`analyze_fw_logs.py`, `analyze_logs.py`), vector database utilities (`ingest_kb.py`), and localized Bash cron orchestration wrappers (`daily_fw_run.sh`, `daily_run.sh`).

## 🚀 Core Pipelines & Use Cases

### 1. Firewall Packet Filter Analysis (`analyze_fw_logs.py`)
Processes layer-3/4 connection states directly from the packet filter engine.
* **Ingestion Signature:** Decodes raw FreeBSD comma-separated arrays via dynamic layer-4 protocol anchoring (`tcp`, `udp`, `icmp`) to cleanly extract source/destination pairs regardless of header length shifts.
* **Posture Modeling:** Automatically calculates high-level volumetric baselines for global `DROP/BLOCK` and `ALLOW/PASS` trends to chart overall security boundaries with zero AI token consumption.
* **AI Evaluation:** Isolates unexpected internal segment movements or localized out-of-band communication attempts, cross-referencing past behaviors to surface structural misconfigurations.

### 2. Suricata IDS Core Intrusion Analysis (`analyze_logs.py`)
Evaluates complex layer-7 application alerts and signatures generated by the Suricata Intrusion Detection engine.
* **Ingestion Signature:** Parses structured EVE JSON output streams focusing on `alert` metadata classifications.
* **AI Evaluation:** Hands off deep signature matches (such as unexpected CVE activity, malicious outbound beaconing, or unauthorized internal scans) to the LLM to deliver detailed architectural mitigations, threat scoring, and precise network isolation steps.
